# План разработки Релиза 3.3 (Gemini 4 Argon) — Видеоплеер Negai

Этот документ содержит структурированное техническое задание и план реализации для релиза **3.3** плеера **Negai** (`app.negai.player`). Предназначено для автоматического разбора и генерации кода в AI Studio.

---

## 🎨 Модуль 1: Унификация UI и эффектов HUD (Компонентный слой Jetpack Compose)

### 1.1. Стеклянный верхний правый блок и кнопка настройки панели
* **Проблема:** Элементы управления в правом верхнем углу плеера и кнопка редактирования панели выбиваются из общего дизайна и не имеют эффекта матового стекла, реализованного на нижней панели.
* **Решение:** 
  * Применить к контейнеру верхнего правого блока (`Row` / `Box`) и кнопке редактирования панели аналогичный нижней панели слой размытия `Modifier.blur()` или общий кастомный `GlassmorphicContainer` (на базе `RenderEffect`).
  * Привести элементы к единому дизайн-коду: унифицировать скругление углов (`RoundedCornerShape`), отступы (`padding`), альфа-канал иконки (`Alpha`) и поведение при фокусе.

### 1.2. Рефакторинг кнопки «Ещё»
* **Требование:** Полностью удалить мини всплывающее меню (`DropdownMenu` / `ExposedDropdownMenu`), привязанное к кнопке «Ещё».
* **Реализация:** Перевести управление на логику перетаскивания (Drag-and-Select, см. Модуль 2).

### 1.3. Обновление кнопки «Масштаб»
* **Требование:** Изменить логику отображения состояний.
* **Реализация:** Заменить строковый ресурс отображения отключенного состояния `откл.` на **«Фактический режим»**.

### 1.4. Модернизация кнопки информации («Инфо»)
* **Требования:**
  * Убрать состояние `откл.` у кнопки информации.
  * Реализовать вывод краткой информации о воспроизводимом файле прямо поверх экрана.
* **Реализация:** Сконструировать легковесный оверлей (`Card` или `Surface` с эффектом матового стекла), выводящий ключевые технические метаданные (текущий кодек, разрешение, битрейт аудио/видео, фреймрейт).

## 👆 Модуль 2: Жесты и новое поведение мини-меню (Drag-and-Select)

### 2.1. Изменение логики взаимодействия с опциями меню
* **Старое поведение:** Клик по кнопке -> открытие выпадающего списка -> клик по элементу.
* **Новое поведение:** Удержание -> скольжение пальцем -> выбор при отпускании.
* **Алгоритм реализации в Jetpack Compose (`PointerInputScope`):**
  1. Перехватить жест через `detectDragGesturesAfterLongPress`.
  2. При **Long Press** — мгновенно отобразить мини-меню рядом с пальцем / кнопкой.
  3. При **Drag** — динамически считывать координаты `pointerInputChange.position`. Вычислять индекс элемента меню, находящегося непосредственно под точкой касания, и применять к нему стейт подсветки (hover/select).
  4. При **Release (отпускании пальца)** — вызвать callback `onReleased` выбранного режима, применить настройку в `NegaiViewModel` и мгновенно скрыть UI мини-меню.

## ⚡ Модуль 3: Плавность UI и оптимизация производительности

### 3.1. Исправление дёрганых слайдеров
* **Проблема:** Ползунки регулировки (громкость, яркость, позиции DSP) перемещаются дёргано и с задержками из-за частых синхронных блокирующих вызовов рекомпозиции и записи в `DataStore`.
* **Решение:** Разделить состояние слайдера на локальное и глобальное.
  * Использовать локальный `mutableFloatStateOf` внутри компонента слайдера для отрисовки перемещения «в реальном времени» (плавно, 65-120 FPS).
  * Обновление глобального стейта в `NegaiViewModel` и запись в репозиторий `PlayerPreferencesRepository` производить строго по событию `onValueChangeFinished` (когда пользователь отпустил слайдер), аналогично логике полосы прокрутки Media3.

### 3.2. Устранение зависания плеера при стриминге
* **Проблема:** При воспроизведении потокового контента (TorrServer P2P / IPTV / HTTP URL) нажатие на кнопку информации о файле вызывает полное зависание (ANR) интерфейса. Это происходит из-за попытки синхронного чтения метаданных контейнера из сетевого сокета в главном UI-потоке.
* **Решение:** 
  * Перенести парсинг треков, чтение свойств `MediaItem` и опрос ExoPlayer-параметров в `viewModelScope` на диспетчер `Dispatchers.IO`.
  * Использовать асинхронные слушатели `Player.Listener` (в частности, `onTracksChanged` и `onMediaMetadataChanged`) для реактивного обновления UI-стейта `PlaybackRuntimeState` без блокирования потока отрисовки.

## 🌐 Модуль 4: Интеграция с системой Android (Внешний плеер)

### 4.1. Конфигурация `AndroidManifest.xml`
Зарегистрировать `PlayerActivity` как обработчик внешних медиа-потоков, добавив интент-фильтры:

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="content" />
    <data android:scheme="file" />
    <data android:scheme="http" />
    <data android:scheme="https" />
    <data android:mimeType="video/*" />
    <data android:mimeType="application/x-mpegurl" />
</intent-filter>
```

### 4.2. Обработка входящих Интентов (`Intent`) в `PlayerActivity`
* **Одиночные серии:** Корректно извлекать `intent.data`, автоматически запрашивать права доступа `Intent.FLAG_GRANT_READ_URI_PERMISSION` и формировать единичный `MediaItem`.
* **Плейлисты и списки серий:**
  * Реализовать парсинг `.m3u` / `.m3u8` файлов, если они передаются через интент.
  * Реализовать чтение `Intent.getClipData()`. Если внешнее приложение (файловый менеджер) передает список из нескольких URI (пакет серий), плеер должен в цикле собрать массив `List<MediaItem>` и передать их в ExoPlayer через `player.setMediaItems(mediaItems)`, обеспечивая корректное переключение между эпизодами.
